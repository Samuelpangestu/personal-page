Case study · 01

One release check for journeys that cross several applications

When each team tests only its own application, the handoffs between applications can go unchecked. I coordinate shared regression checks so a release is judged on the whole journey.

Problem
A user journey passes through applications owned by different teams. Each part can pass its own tests while the journey still fails.
My role
Coordinate the shared regression checks across the teams involved and bring the results into one release review.
Approach
Map each shared journey end to end and include the handoffs between applications in the regression scope.
Release review
Four questions: scope, test evidence, open risks, and the decision with its reason. The template is below.

Case study · 02

From a test request to results the team can use

When several teams share automated tests, it can be hard to tell what ran and why a check failed. I helped build a workflow that keeps each test request, its status, and its results together.

  1. Requested

    Request a test run

    A team member chooses what to test. The request is queued so the team can see it is waiting to run.

  2. Running

    Run the checks

    A test runner picks up the request, runs the selected checks, and reports their status.

  3. Ready for review

    Review the results

    The team sees which checks passed or failed and uses the run's reports or logs to investigate failures.

Case study · 03

AI-assisted test triage, with a person in the loop

When an automated test fails, someone has to work out whether the product, the test, the test data, or the environment broke. I'm building an agent workflow that gathers evidence first and stops for a reviewer before changing what counts as a pass.

  1. 01

    Collect evidence

    Read the trace, logs, and request ID before guessing. An API 500 sends it to the server logs for that request.

  2. 02

    Classify the failure

    Decide whether the product, the test, the test data, or the environment is the likely cause.

  3. 03

    Act within limits

    Restore test data and rerun, or propose a repair such as updating how the test finds a renamed button. The original checks stay in place.

  4. 04

    Stop for review

    A change to what counts as a passing result waits for a reviewer. Without enough evidence, the agent escalates instead of assigning a cause.
