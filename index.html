Case study · 01

From a test request to results the team can use

When several teams share automated tests, it can be hard to tell what ran and why a check failed. I helped build a workflow that keeps each test request, its status, and its results together.

  1. 01

    Request a test run

    A team member chooses what to test. The request is queued so the team can see it is waiting to run.

  2. 02

    Run the checks

    A test runner picks up the request, runs the selected checks, and reports their status.

  3. 03

    Review the results

    The team can see which checks passed or failed and use the reports or logs from the run to investigate failures.
